ZED 相機功能 (ZED Camera)(大人型)

備註

本章節功能為 大人型專用。小人型機器人未配備 ZED 深度相機，以下 API 不存在。

重要

影像座標系為 960 x 600。 其他章節標示的 0~320 / 0~240 為小人型的解析度。 色模、深度、疊合三套系統共用同一組座標，可以直接互相對照 —— 例如拿色模算出的物體中心去查 API.depth_at()，得到的就是該物體的距離。

三套偵測系統的索引結構完全相同：[類別索引][該類別的第幾個物體]。 第二層的順序是連通元件的掃描順序（由上而下、由左而右）， 不代表大小或遠近，也不保證跨幀穩定，需要「最大的」或「最近的」請自行挑選。

存取前務必先檢查對應的 *_counts，數量為 0 時清單是空的。

色模擴充欄位

色模本身的用法請見 視覺與感測器數據 (Vision & Sensors)，以下三個欄位為大人型額外提供。

API.object_cx: List[List[int]]

各顏色類別物體邊界框的中心 X 座標清單。

這是一個二維清單，第一層為顏色索引，第二層為該顏色的第幾個物體。 數值範圍介於 (0 ~ 960) 之間。

範例

>>> # 取得第一個橘色物體的中心，用來對準頭部
>>> if api.color_counts[api.ORANGE] > 0:
>>>     cx = api.object_cx[api.ORANGE][0]
>>>     offset = cx - 480      # 480 為畫面中心
API.object_cy: List[List[int]]

各顏色類別物體邊界框的中心 Y 座標清單。

這是一個二維清單，第一層為顏色索引，第二層為該顏色的第幾個物體。 數值範圍介於 (0 ~ 600) 之間。

範例

>>> if api.color_counts[api.RED] > 0:
>>>     cy = api.object_cy[api.RED][0]
API.object_ratio: List[List[float]]

各顏色類別物體邊界框的寬高比 (寬 / 高) 清單。

用於形狀判斷，可過濾掉輪廓明顯不符的雜訊：

  • 約 1.0：接近正方形或圓形（例如球）

  • 遠小於 1：窄而高（例如直立的桿子、門柱）

  • 遠大於 1：寬而扁（例如橫躺的橫桿、地面線條）

範例

>>> # 只保留形狀接近圓形、且面積夠大的橘色目標
>>> balls = [i for i in range(api.color_counts[api.ORANGE])
...          if api.object_sizes[api.ORANGE][i] > 3000
...          and 0.7 < api.object_ratio[api.ORANGE][i] < 1.4]

深度偵測 (Depth)

依距離區間 D1~D8 將畫面分類，區間範圍在網頁的深度模式中設定。 除了與色模相同的邊界、面積等欄位外，額外提供每個物體的實際距離。

API.depth_at(x: int, y: int, radius: int = 5) → float | None

查詢影像上任一點的深度，單位公分。

預設取該點周圍 (2*radius+1) 見方鄰域的**中位數**而非單一像素值。 ZED 深度圖有不少單像素的洞與雜訊，直接取單點很容易剛好打在無效值上， 中位數對這兩者都免疫。

參數:

  • x (int) -- 影像 X 座標，範圍 0~960（與 object_x_min 等同一座標系）。

  • y (int) -- 影像 Y 座標，範圍 0~600。

  • radius (int) -- 取樣半徑。0 表示只取該點；預設 5 即 11x11 鄰域。

回傳:

float | None -- 距離（公分）。座標超出範圍、尚未收到深度圖、 或鄰域內全是無效值時回傳 None。

範例

>>> # 查一個色模物體中心的距離
>>> cx = api.object_cx[api.RED][0]
>>> cy = api.object_cy[api.RED][0]
>>> d = api.depth_at(cx, cy)
>>> if d is not None and d < 80:
>>>     print("紅色目標在 80 公分內")
API.distance_counts: List[int]

各距離類別偵測到的物體總數清單。

距離類別 D1~D8 的範圍在網頁的深度模式中設定，儲存於各 strategy 的 depth.ini。這 8 個區間與色模的 8 種顏色是**各自獨立**的分類系統， 只是數量恰好相同。

  • 距離索引對照表：api.D1 ~ api.D8（即 0 ~ 7）

範例

>>> # 檢查最近的距離區間內有沒有東西
>>> if api.distance_counts[api.D1] > 0:
>>>     print(f"D1 區間偵測到 {api.distance_counts[api.D1]} 個物體")
API.distance_cm: List[List[int]]

各距離類別物體的平均距離清單，單位為**公分**。

取該物體所有有效深度像素的平均值。因為物體本來就被距離區間框住， 平均值必定落在該區間內。

範例

>>> # 取得 D1 區間中最近的那個物體
>>> n = api.distance_counts[api.D1]
>>> if n > 0:
>>>     j = min(range(n), key=lambda i: api.distance_cm[api.D1][i])
>>>     print(f"最近的物體在 {api.distance_cm[api.D1][j]} 公分處")
API.distance_min_cm: List[List[int]]

各距離類別物體**最近端**的距離，單位為公分。

與 distance_max_cm 一起看可判斷物體的深度延伸範圍。 正對鏡頭的球兩者會很接近；斜向的牆面則會相差很大。

API.distance_max_cm: List[List[int]]

各距離類別物體**最遠端**的距離，單位為公分。

API.distance_x_min: List[List[int]]

各距離類別物體邊界框的最小 X 座標 (左邊界)，範圍 (0 ~ 960)。

API.distance_x_max: List[List[int]]

各距離類別物體邊界框的最大 X 座標 (右邊界)，範圍 (0 ~ 960)。

API.distance_y_min: List[List[int]]

各距離類別物體邊界框的最小 Y 座標 (上邊界)，範圍 (0 ~ 600)。

API.distance_y_max: List[List[int]]

各距離類別物體邊界框的最大 Y 座標 (下邊界)，範圍 (0 ~ 600)。

API.distance_cx: List[List[int]]

各距離類別物體邊界框的中心 X 座標，範圍 (0 ~ 960)。

API.distance_cy: List[List[int]]

各距離類別物體邊界框的中心 Y 座標，範圍 (0 ~ 600)。

API.distance_sizes: List[List[float]]

各距離類別物體的面積（像素數）清單。用法同 object_sizes。

API.distance_ratio: List[List[float]]

各距離類別物體的寬高比 (寬 / 高)，判讀方式同 object_ratio。

API.new_distance_info: bool

深度偵測是否有新資料的旗標，用法同 new_object_info。

疊合偵測 (Overlap)

Set1~Set8 各自綁定一個顏色類別與一個距離類別，取兩者的交集區域， 用於「這個顏色、而且在這個距離」的複合條件判斷。 組合內容在網頁的疊合模式中設定。

API.overlap_counts: List[int]

各疊合組合偵測到的交集區塊總數清單。

每一組 Set 綁定一個顏色類別與一個距離類別，交集即「顏色符合且距離也符合」 的區域。組合內容在網頁的疊合模式中設定，儲存於各 strategy 的 overlap.ini。

  • 組合索引對照表：api.SET1 ~ api.SET8（即 0 ~ 7）

備註

僅在色模為 All_color、深度為 All_distance、疊合為 All_overlap 時更新，且只計算已勾選 Enable 的組合。

範例

>>> # Set1 設定為「紅色 x D1」時，代表 1.5 公尺內的紅色目標
>>> if api.overlap_counts[api.SET1] > 0:
>>>     print("找到近距離的紅色目標")
API.overlap_cm: List[List[int]]

各疊合組合交集區塊的平均距離，單位為公分。

範例

>>> # 取得 Set1 中面積最大的目標，並取得其中心與距離
>>> n = api.overlap_counts[api.SET1]
>>> if n > 0:
>>>     j = max(range(n), key=lambda i: api.overlap_sizes[api.SET1][i])
>>>     cx = api.overlap_cx[api.SET1][j]
>>>     distance = api.overlap_cm[api.SET1][j]
API.overlap_min_cm: List[List[int]]

各疊合組合交集區塊**最近端**的距離，單位為公分。

API.overlap_max_cm: List[List[int]]

各疊合組合交集區塊**最遠端**的距離，單位為公分。

API.overlap_x_min: List[List[int]]

各疊合組合交集區塊的最小 X 座標 (左邊界)，範圍 (0 ~ 960)。

API.overlap_x_max: List[List[int]]

各疊合組合交集區塊的最大 X 座標 (右邊界)，範圍 (0 ~ 960)。

API.overlap_y_min: List[List[int]]

各疊合組合交集區塊的最小 Y 座標 (上邊界)，範圍 (0 ~ 600)。

API.overlap_y_max: List[List[int]]

各疊合組合交集區塊的最大 Y 座標 (下邊界)，範圍 (0 ~ 600)。

API.overlap_cx: List[List[int]]

各疊合組合交集區塊的中心 X 座標，範圍 (0 ~ 960)。

API.overlap_cy: List[List[int]]

各疊合組合交集區塊的中心 Y 座標，範圍 (0 ~ 600)。

API.overlap_sizes: List[List[float]]

各疊合組合交集區塊的面積（像素數）清單。

API.overlap_ratio: List[List[float]]

各疊合組合交集區塊的寬高比 (寬 / 高)。

API.new_overlap_info: bool

疊合偵測是否有新資料的旗標，用法同 new_object_info。

ZED 內建 IMU

ZED 相機內建一顆 IMU，與機身上的 Arduino IMU（API.imu_rpy）是兩顆獨立的感測器。

警告

ZED 安裝在**頭部雲台**上，頭部轉動時即使機身未移動 yaw 也會改變， 兩顆 IMU 的數值不能直接互相比較。

API.sendZedSensorReset() → None

將 ZED IMU 目前的姿態設為零點。

與 sendSensorReset()（Arduino IMU）互不影響，兩顆感測器各自歸零。 歸零後 zed_imu_rpy 會變成 0，zed_imu_abs_rpy 則維持絕對值不變。

API.zed_imu_rpy: List[float]

ZED 相機內建 IMU 的姿態數值（單位：度），已套用歸零。

  • [0] roll：翻滾角

  • [1] pitch：俯仰角

  • [2] yaw：偏航角

歸零請呼叫 sendZedSensorReset()。

警告

這與 imu_rpy（機身上的 Arduino IMU）是**兩顆不同的感測器**， 且 ZED 安裝在頭部雲台上 —— 只要頭部轉動，即使機身沒動 yaw 也會改變。 兩者的數值不能直接互相比較。

範例

>>> current_roll = api.zed_imu_rpy[0]
API.zed_imu_abs_rpy: List[float]

ZED 內建 IMU 未歸零的絕對姿態（單位：度），索引順序同 zed_imu_rpy。

roll 與 pitch 以重力為基準，屬於絕對值，可用來判斷相機真實的傾斜程度； yaw 沒有絕對基準（無磁力計校正），會隨時間漂移。

API.zed_gyro: List[float]

ZED 內建 IMU 的角速度 [x, y, z]，單位為 deg/s（原生 rad/s 已換算）。

靜止時三軸都應接近 0，可用於偵測劇烈晃動或跌倒。

API.zed_accel: List[float]

ZED 內建 IMU 的線加速度 [x, y, z]，單位為 m/s²，數值含重力。

靜止且水平放置時 z 軸約為 9.81，可作為感測器是否正常運作的快速檢查。

API.zed_imu_zeroed: bool

ZED IMU 是否已設定過零點。開機後尚未呼叫 sendZedSensorReset() 前為 False。

視覺里程計 (Odometry)

ZED 以視覺特徵搭配 IMU 融合估算相機的位移。

警告

目前為**驗證階段**，尚未做頭部雲台的補償。回傳的是相機而非機身的位移， 只轉頭不移動時數值同樣會變化；走路時的晃動與場地特徵稀少也會影響精度。 請勿讓策略依賴此數值。

API.sendOdomReset() → None

把 ZED 視覺里程計歸零（呼叫 /zed/zed_node/reset_odometry）。

非阻塞：服務尚未就緒時只記錄警告，不會卡住策略主迴圈。

API.odom_xyz: List[float]

ZED 視覺里程計的位移 [x, y, z]，單位為**公分**。

相對於節點啟動時的位置，或最近一次 sendOdomReset() 的位置。

警告

這是**相機**的位移，而相機安裝在頭部雲台上 —— 只轉頭而機身不動時 數值同樣會變化。此外人形機器人走路時的晃動會影響視覺里程計的精度， 場地特徵稀少時也可能漂移。目前僅供觀察驗證，請勿讓策略依賴此數值。

範例

>>> api.sendOdomReset()
>>> # ... 讓機器人前進一段距離 ...
>>> print(f"前進了約 {api.odom_xyz[0]:.1f} 公分")
API.odom_yaw: float

ZED 視覺里程計的偏航角，單位為度。

與 odom_xyz 相同，這是**相機**而非機身的朝向。

內部處理函式

以下為 API 內部使用的回呼與統計函式，策略端不需要直接呼叫。

API._depth_det_callback(msg: std_msgs.msg.String, label: str) → None

/depth_detections/{D1~D8} 的回呼。

API._overlap_det_callback(msg: std_msgs.msg.String, label: str) → None

/overlap_detections/{Set1~Set8} 的回呼。

API._json_det_callback(msg, label, latest, stamps, recompute)

detections JSON 的共用解析（色模以外的兩套共用）。

API._fill_stats(labels, latest, counts, sizes, x_min, x_max, y_min, y_max, cx_l, cy_l, ratio_l, cm_l, cm_min_l, cm_max_l, tag)

把 detections JSON 攤平成與色模相同形狀的平行清單。

深度與疊合的 JSON 欄位與色模完全相同，只是多了 distance_* 三個欄位， 所以這裡用同一套邏輯處理，避免三份幾乎一樣的程式碼。

API._recompute_distance_stats() → None

重算 D1~D8 的統計，欄位形狀與色模一致。

API._recompute_overlap_stats() → None

重算 Set1~Set8 的統計，欄位形狀與色模一致。

API._depth_mm_cb(msg: sensor_msgs.msg.Image) → None

快取 /depth_mm（裁切對齊後的公釐深度圖），供 depth_at() 使用。

API._zed_imu_cb(msg: tku_msgs.msg.ZedImu) → None

/zed_imu/data 的回呼，來源是 zed_imu_node。

API._odom_cb(msg: nav_msgs.msg.Odometry) → None

/zed/zed_node/odom 的回呼，把位移換算成公分、朝向換算成度。
